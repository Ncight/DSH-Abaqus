# 不排水粘土地基上条形基础的极限承载力

帮我用 Abaqus 算一个地基极限承载力的验证算例：饱和粘土不排水条件下，刚性条形基础压到地基整体破坏，我要每延米的极限荷载。

## 单位制

m–t–s 单位制：长度 m，力 kN，应力和模量 kPa。

## 模型

- 基础：刚性条形基础，宽 B = 2 m，置于地表（无埋深），平面应变问题。
- 地基土：饱和粘土，不排水总应力分析；不排水抗剪强度 cu = 100 kPa（φu = 0），理想弹塑性；弹性模量 E = 30000 kPa；不排水条件下体积不可压缩（泊松比取接近 0.5 的值）。不考虑土的自重。
- 地基范围自己定，但要保证边界不影响破坏机构。
- 坐标约定（请照此建模，我们按这个约定读结果）：地表为 y = 0，土体在 y < 0 一侧；基础中心线在 x = 0，基底占据 |x| ≤ 1 m。可以利用对称性只建 x ≥ 0 的一半，但 `result.json` 里要填整个基础每延米的荷载。
- 加载：竖向中心荷载，用位移控制把基础竖直向下压，一直压到地基达到极限状态（荷载不再增长而沉降继续发展）。基础是刚性的：基底各点的竖向位移相同。小变形分析即可。
- 单元类型和网格自定。

## 交付要求

1. 所有工作都在当前目录下完成，模型必须真正提交 Abaqus 求解，不能只给理论值。
2. 作业名（job name）必须是 `footing`，求解完成后当前目录下应有 `footing.odb`，作业必须正常算完。
3. ODB 中要保留加载全过程的位移 U 和反力 RF 场输出（不要只存最后一帧），最后一帧必须已经处在极限状态。具体判据是：在加载分析步最后 15% 的过程里（按分析步时间计），基础荷载的变化不超过 2%，而基础沉降至少再增大 5%。我们会直接读 ODB 的反力和位移来核对。
4. 从计算结果中提取下面这个量，写入当前目录下的 `result.json`。文件内容是一个 JSON 对象，值为数字（不要写成字符串，不要带单位），取正值：

| 键 | 含义 | 单位 |
|---|---|---|
| `ultimate_load_kN_per_m` | 整个基础（全宽 2 m）每延米的极限荷载 | kN/m |

示例格式：`{"ultimate_load_kN_per_m": 1234.5}`（数值仅示意格式）。

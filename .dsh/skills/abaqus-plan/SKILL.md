# 需求澄清与建模方案

## 什么时候先问、什么时候直接做

- 任务书已经把下面清单里的项目写全了 → 直接做，不要反复确认。
- 有缺项，而且不同的理解会让结果明显不同 → 一次问清（把问题列成编号清单，每个问题给出你建议的默认值，方便用户只回"按默认"）。
- 缺的只是不影响结果的细节（部件怎么命名、坐标轴朝哪）→ 自己定，在报告里说明。

## 澄清清单

1. **目的与关心的量**：要位移、应力、频率、承载力、还是接触压力？在什么位置？精度要求（定性看趋势 / 5% / 1%）？
2. **分析类型**：静力 / 模态 / 屈曲 / 隐式动力 / 显式动力；线性还是要考虑几何、材料、接触非线性。
3. **几何与理想化**：尺寸；三维实体、壳、梁，还是平面应力 / 平面应变 / 轴对称；能否用对称性。
4. **材料**：弹性常数、密度；是否进入塑性或损伤（需要曲线/参数）；阻尼。
5. **单位制**：没指定时用本项目默认的 m–t–s（kN、kPa、t/m³）。
6. **边界条件**：每个支承是固支、铰支、滑动还是弹性；有没有对称面。
7. **载荷**：大小、方向、作用位置、是合力还是分布值；加载顺序；动力载荷的时程。
8. **部件之间的关系**：绑定、接触（摩擦系数）、还是没有关系。
9. **交付物**：作业名、结果文件格式与键名、需要哪些图。

## 一页建模方案（复杂任务动手前给用户看）

```
## 建模方案：<题目>
1. 目标：要回答的问题，关心的结果量与位置，精度要求
2. 理想化：维度与单元族（实体/壳/梁/平面/轴对称）、是否用对称、简化掉了什么
3. 材料与单位制：各材料参数（带单位），单位制
4. 边界与载荷：逐条列出，标明作用位置和数值；加载顺序
5. 部件关系：Tie / 接触（主从面、摩擦）
6. 网格：单元类型、关键区域尺寸、预计单元数；准备怎么验证网格收敛
7. 分析步：类型、是否几何非线性、时间/增量设置
8. 输出：场量、历程量、要出的图
9. 预估结果：手算或量级估计（位移、应力、频率、反力），以及预计计算耗时
10. 验收标准：与预估的允许偏差、能量/平衡检查、需要用户在预览面板确认的要点
11. 待确认的问题：<编号清单，各带建议默认值>
```

方案被用户确认后再建模。建模过程中发现方案里的假设不成立（例如必须考虑大变形），先告诉用户再改。

## 人工审查怎么配合

模型导出 INP 并通过 `abq check`、`abq datacheck` 后，用三五行向用户概括：几何与尺寸、材料参数与单位制、边界与载荷（位置和数值）、接触/绑定、网格规模与单元类型，并附 `abq render job.inp` 生成的模型图。然后请用户在预览面板里审查。用户批准后再 `abq run`；被退回就按审查意见单逐条修改。
